## Architecture review and bounds

### Precise presentation/integration boundary

The Vue application imports typed local fixtures; it has no backend request adapter, development proxy, CORS policy or live measurement source. Its illustrative pulse and event times are explicitly labeled, and the consumer scenario is future-only. Existing backend contracts are unauthenticated GET /health (liveness), opt-in POST /operator/replays (authorized durable re-enablement) and actor-scoped GET /operator/replays/{request_id} (receipt observation); none provides the read-only delivery projection required by the presentation. No browser integration test against those privileged routes is claimed.

A bounded follow-up should first agree an authenticated read-only projection: allowed event fields without payload/credentials, stable identity, lifecycle and ownership interpretation, observation timestamp, pagination/body bounds and unavailable/uncertain responses. Then implement one frontend adapter for that projection with explicit live versus simulated labels, server-side credentials, request cancellation and stale-response protection. Define same-origin deployment or a narrowly scoped read-only CORS policy separately; privileged replay routes remain outside that browser boundary. This proposal does not add a dashboard, login provider or destructive controls during closure.

Domain values validate history, identity-related ownership and microsecond times; transport validates credentials/intent/body; application ports stay focused and driver-independent; composition owns pools and publisher lifecycle. PostgreSQL adapters implement lock/clock/representation/error semantics; Lapin owns connection/channel/confirm details. Concrete helpers are reused for beginning transactions, sampling authoritative time, decoding stored timestamps/JSON and classifying commits. No cosmetic layer rewrite or dependency update was required.

Inspected arithmetic/conversions, revision/ownership predicates, terminal transitions, retry decisions, reconnection, cancellation, task admission and sanitized formatting. Tests prove that dead_letter is not reported as completion and uncertainty is not automatically retried. A representable counter/revision does not promise unlimited progress: exhausted revision capacity or unsupported data requires operator review. The observation reader can return leased pending snapshots and must not be used as an acquisition port. Payloads and retained outbox/audit history have no byte/retention policy; these are explicit hardening gaps, not newly claimed bounds.

## Study path and next milestone

Start with the normal isolated delivery example in [integrated_recovery](../../../backend/tests/integrated_recovery.rs): seed an ID, acquire, observe broker JSON/message_id, and independently inspect processed. Then follow [composition](../../../backend/src/bin/relay.rs) → [worker](../../../backend/src/application/worker.rs) → [deliver_once](../../../backend/src/application/delivery.rs) → [ownership contracts](../../../backend/src/persistence/ownership.rs) / [publisher port](../../../backend/src/application/publisher.rs) → PostgreSQL and RabbitMQ adapters. Use the matrix to jump from each invariant to its regression.

Next compare five concrete schedules: crash after broker acceptance; expired owner versus fresh token; mandatory return and delayed eligibility; unsafe prefix versus fresh isolation; authorized replay with lost COMMIT acknowledgement and repeated receipt. Read [ADR 007](../adr/007-durable-delivery-ownership.md), [ADR 008](../adr/008-durable-failure-policy.md), [ADR 009](../adr/009-authorized-idempotent-replay.md) alongside the test observations. Rust learning topics are newtypes, Result/match, traits with Send futures, async cancellation and ownership; distributed-systems decisions are separate: commit boundaries, leases, stable identity, uncertainty and downstream deduplication. The presentation illustrates these decisions but is not their runtime evidence.

Milestone 4 starts with a demonstrative business consumer on isolated topology, bounded prefetch and manual acknowledgement after an atomic local transaction. Define the local effect and a unique stable-event-ID deduplication record, commit them together, and validate duplicate delivery, concurrent duplicates, crash before commit, crash after commit/before ACK, reconnect and broker redelivery. Preserve original event identity and acknowledge duplicates only after observing the committed deduplication result. Replay with that same event ID may intentionally produce **no additional effect** if the consumer already committed it. External effects need their own protocol and cannot inherit that local atomicity. Producer API, live dashboard, repair, throughput, retention, HA/TLS and production hardening remain separately scoped work.

References explain mechanisms; executed project evidence above establishes only the tested application behavior.
